Topic 2D — Introduction ⏱ 0:00 – 1:30

What is "Defensive Validation"?

1
Client-Side Validation Zod · React
Instant UI feedback before the request even leaves the browser. Improves user experience — catches typos immediately.
2
Server-Side Validation Zod · Express
The only reliable filter. Anyone can bypass the frontend using Postman, cURL, or scripts. The server must validate independently.
3
Database Constraint Prisma · PostgreSQL
The final safety net. A database-level unique constraint catches race conditions that even server code cannot reliably prevent alone.
🇧🇩 ডিফেন্সিভ ভ্যালিডেশন মানে — আমরা ধরে নেব যে যেকেউ যেকোনো সময় ভুল বা ক্ষতিকর ডাটা পাঠাতে পারে। তাই আমরা ৩টি আলাদা স্তরে নিরাপত্তা প্রাচীর তৈরি করব।

import { z } from 'zod';

const submissionSchema = z.object({
  projectName: z.string().min(3, 'Min 3 characters required'),
  repoUrl: z.string().url('Must be a valid GitHub URL'),
  liveUrl: z.string().url().optional().or(z.literal('')),
  description: z.string().min(10, 'Min 10 characters required'),
});

// On form submit:
const result = submissionSchema.safeParse(formData);
if (!result.success) {
  // Set field-level errors → red messages below each input
  setErrors(result.error.flatten().fieldErrors);
  return; // ← never hits the API
}

Topic 2D — Server Validation ⏱ 4:00 – 6:30

Layer 2: Backend Zod Validation

server/src/schemas/index.ts

❌ Why not just frontend?

Anyone can open DevTools, disable JS, or use Postman / cURL to bypass the React form entirely and send raw JSON to /api/submissions with malformed or malicious data.

✅ Server is the only truth

The server never trusts the client. Even if the frontend sends garbage, the backend Zod schema rejects it before it can touch the database.

📄 schemas/index.ts — createSubmissionSchema
export const createSubmissionSchema = z.object({
  projectName: z.string().min(3).max(100),
  repoUrl: z.string().url()
    .refine(url => !url.startsWith('javascript:'), {
      message: 'Invalid protocol' // XSS block
    }),
  liveUrl: z.string().url().optional().nullable(),
  description: z.string().min(10).max(1000),
});

// In controller:
const parsed = createSubmissionSchema.safeParse(req.body);
if (!parsed.success)
  return res.status(400).json({ errors: parsed.error.flatten() });
🇧🇩 ব্যাকএন্ড z.string().url() দিয়ে URL ভ্যালিড করে এবং javascript: প্রোটোকল ব্লক করে XSS আক্রমণ প্রতিরোধ করে।

📄 submission.controller.ts — normalize function
function normalizeUrl(url: string): string {
  return url
    .trim() // remove spaces
    .toLowerCase() // case-insensitive
    .replace(/\.git$/, '') // strip .git
    .replace(/\/+$/, ''); // strip trailing slash
}
const normalizedRepo = normalizeUrl(parsed.data.repoUrl);

Topic 2D — Database Layer ⏱ 6:30 – 8:30

Layer 3: Database-Level Protection

server/prisma/schema.prisma · Race Condition Defence

📄 schema.prisma — compound unique
model Submission {
  id String @id @default(cuid())
  studentId String
  repoUrl String
  ...

  @@unique([studentId, repoUrl])
  // One student, one repo — guaranteed by DB
}
📄 Controller — Prisma P2002 catch
try {
  await prisma.submission.create({ data });
} catch (err) {
  if (err.code === 'P2002') {
    return res.status(409).json({
      message: 'You have already submitted this repository.'
    });
  }
  throw err;
}
⚡
The Race Condition Problem
Two requests arrive at the same millisecond. Both pass the server's existingCheck. Both insert — creating a duplicate. Code-level checks alone cannot prevent this.
🗄️
The Database Fix
@@unique([studentId, repoUrl]) makes PostgreSQL enforce the constraint atomically. The second insert always fails with P2002 — no matter the timing.
🇧🇩 @@unique([studentId, repoUrl]) — একজন স্টুডেন্ট একই রিপোজিটরি দুইবার কখনো সাবমিট করতে পারবে না। Race Condition হলেও ডাটাবেজ P2002 এরর দেয় → আমরা 409 Conflict রিটার্ন করি।
