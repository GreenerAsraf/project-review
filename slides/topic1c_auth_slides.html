Topic 1C — Core Concept ⏱ 0:00 – 1:30

AuthN vs AuthZ — What's the Difference?

🛂
Authentication (AuthN)
WHO ARE YOU?
Verifying the identity of a user.

✈️ Like the security officer checking your passport at the airport gate.
Login JWT Issued Password Check
🎫
Authorization (AuthZ)
WHAT CAN YOU DO?
Controlling what an identified user is permitted to access.

🪑 Your boarding pass allows Economy only — you cannot enter the cockpit.
Role Check Resource Guard 403 Forbidden
🇧🇩 সহজ কথায়: Authentication হলো "আপনি কে?" নিশ্চিত করা। Authorization হলো "আপনি কী করতে পারবেন?" নির্ধারণ করা। এই দুটো ধাপ সবসময় আলাদা এবং উভয়ই বাধ্যতামূলক।

Role-Based Access Control in ProjectPilot

🎓
STUDENT Role
  • ✅ Submit new projects
  • ✅ View own submissions only
  • ✅ See status (PENDING / APPROVED / REJECTED)
  • ❌ Access mentor dashboard
  • ❌ Approve or reject submissions
👨‍🏫
MENTOR Role
  • ✅ View ALL student submissions
  • ✅ Filter by status (server-side)
  • ✅ Approve or Reject any submission
  • ✅ View aggregated statistics
  • ❌ Cannot be created via public signup

Topic 1C — Middleware ⏱ 3:45 – 6:00

Middleware Implementation

server/src/middlewares/auth.ts

📄 middlewares/auth.ts
// ── Middleware 1: AuthN ──────────────────────────────
export const authenticateJWT = (req, res, next) => {
  const token = req.headers.authorization?.split(' ')[1];
  if (!token) return res.status(401).json({ message: 'Unauthorized' });
  const decoded = jwt.verify(token, process.env.JWT_SECRET!);
  req.user = decoded; // { id, email, role }
  next();
};

// ── Middleware 2: AuthZ ──────────────────────────────
export const requireRole = (role: 'STUDENT' | 'MENTOR') => (req, res, next) => {
  if (req.user?.role !== role) {
    return res.status(403).json({ message: 'Forbidden: Insufficient role' });
  }
  next();
};
🇧🇩 authenticateJWT → Bearer Token ডিকোড করে — ইউজার লগইন করা কিনা নিশ্চিত করে (AuthN)।
requireRole('MENTOR') → টোকেনের ভেতরের role চেক করে — স্টুডেন্ট হলে সাথে সাথে 403 Forbidden (AuthZ)।
Topic 1C — Architecture Lesson ⏱ 6:00 – 8:15

⚠️ Frontend Guards Are NOT Enough!

❌ Wrong (Junior Dev Mistake)
// Next.js — only blocks UI nav
if (user.role !== 'MENTOR')
  router.push('/login');

Attacker never uses your UI. They hit the API directly with Postman / cURL.

✅ Correct (Server-side Guard)
// Express — enforced at API level
router.get('/mentor/submissions',
  authenticateJWT,
  requireRole('MENTOR'),
  mentorController.getSubmissions);

Security boundary lives on the server. Only the verified JWT payload is trusted.

  • 🖥️
    Frontend Guard
    UX only — prevents accidental nav
  • 🔒
    Backend Middleware
    Real security — always enforced
  • 🎟️
    JWT Payload
    Server never trusts client-sent role

Topic 1C — Viva Defense ⏱ 8:15 – 10:00

🎤 Viva Q&A Defense

  • ❓
    "JWT টোকেন যদি কেউ চুরি করে?"
    ✅ Use short-lived tokens · Force HTTPS · Prefer HttpOnly Secure Cookie over localStorage in production.
  • ❓
    "কেন ফ্রন্টএন্ডে রোল চেক করলেই হয় না?"
    ✅ Attackers bypass UI via Postman/cURL. Only reliable security boundary is the server.
  • ❓
    "JWT vs Session — কোনটি ভালো?"
    ✅ JWT = stateless, scales well, no DB per request. Sessions = stateful, easier revocation. Depends on architecture.
  • ❓
    "RBAC আর ABAC-এর পার্থক্য কী?"
    ✅ RBAC = access by Role. ABAC = access by Attributes (time, IP, owner, etc.) — more granular.
